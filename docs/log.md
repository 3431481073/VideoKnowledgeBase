## 三、🔴 一处对方案的偏离（报备）

**方案写的是「删 `build\`」，「删前确认 `build_exe.ps1` 和 `VideoKnowledgeBase.spec` 还在」。**

**执行时发现：这两个文件就在 `build\` 里面。**

**`build\build_exe.ps1` 不是产物 —— 它是构建脚本本身**，而且：

| 事实 | 后果 |
| --- | --- |
| 它用 `$Root = Split-Path -Parent $PSScriptRoot` 推导项目根 | **搬走它，项目根就算错** |
| 它把输出写回 `Join-Path $Root "build\dist_$Mode"`（第 37-38、87 行） | **它必须待在 `<root>\build\`** |
| 里面有 4,409 B 的实测知识（onefile/onedir 取舍分析、`webui\media` 联接的防护逻辑） | **不是可再生的** |
| **它不在 git 里**（`?? build/`）**也不在方案给的备份清单里** | 🔴 **按字面删掉 = 永久销毁** |

**→ 处置：**

1. **先把 `build_exe.ps1` + `.spec` 复制进备份**（`_rollback\videoknowledgebase_before_20261003\build\`，5,433 B，SHA256 已核）；
2. **只删四个 PyInstaller 产物目录**（`dist_onedir` 31.41 + `dist_onefile` 14.34 + `work_onedir` 16.32 + `work_onefile` 20.80 = **82.87 MB**）；
3. **保留 `build\` 与那两个文件**；
4. **`.gitignore` 里加的不是 `build/`，而是 `build/dist_*/` 和 `build/work_*/`** ——
   **写成 `build/` 会把构建脚本一起忽略掉。**

**净效果与方案一致（回收 82.87 MB），但保住了一个方案没打算保住的东西。**

### 附：怎么确认"跑的是不是新构建"（这次差点被绕进去）

$p = (Get-NetTCPConnection -OwningProcess <PID> -State Listen).LocalPort
(Invoke-WebRequest "http://127.0.0.1:$p/js/process_dialog.js" -UseBasicParsing).RawContentLength

1. `$r.Content.Length` 是**字符数**不是字节数 —— 中文 UTF-8 三字节/字，

# 导入"偶发不显示" + ✕ 不再确认 · 2026-10-13

## 一、✕ 去掉确认框

用户："在导入界面这个删除就直接删了就行，不需要确认。"

`dequeueRow` 里的 `askConfirm` 整段删掉 —— 点了立刻生效，状态行给一句回执
（"已从处理列表移除「X」（导图和视频都没动）"）。**敢不确认是因为它不删任何东西、
而且可逆** —— 这正是上一轮把两个动作分开换来的。

## 二、导入偶发不显示：**根因是前端把好数据扔了**

用户原话："某一次导入会失效，再导一个两条一起冒出来；有时正常，有时导入一个之后
卡着就没显示。"

### 根因（`webui\js\app.js` 轮询回调）

```js
var p = await VKB.call('poll');
if (!p || !p.changed) return;      // ← 元凶
```

后端 `poll()` 是**无条件**把 `light()`（导入进度 / 列表 / 摄像头 / 事件）拼进返回值
的 —— **数据每一轮都是新的，是前端自己整包扔掉的**。只要 `changed` 有一次算错
（导入完成得比两次轮询还快、文件对话框把 UI 线程堵住让轮询积压后一起回来……），
界面就**冻住**，直到下一次别的事件把它顶开 —— 积压的东西一起冒出来。

### 三处一起修

| # | 改哪 | 改成什么 |
| --- | --- | --- |
| 1 | `app.js` 轮询 | **轻的东西每轮都灌**（导入进度 / 摄像头 / 事件 / 每行进度）；`changed` 只用来决定**要不要做重活（整表重渲染）**。界面不可能再"漏掉一次更新" |
| 2 | `web_state._import_touch()` | 导入**不是队列任务**，以前靠"轮询恰好撞上 active 那一下"刷新。现在在**每次状态变化**（起点 / 每个进度回调 / 每条导入完 / 结束）主动 `jobs.touch()`，把时间窗消掉 |
| 3 | `process_dialog.doImport` | 点完导入**当场**把占位行画出来（+ 状态行回执），不等下一次轮询。失败时也把 `r.error` 说出来（以前只说"导入未开始"，等于没说） |
